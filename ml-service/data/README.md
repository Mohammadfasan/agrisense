# data

The crop-disease image corpus, and the split the classifier is trained on.

**No images are in git.** Everything under `raw/` and `processed/` is ignored;
the directories are kept by `.gitkeep` so a fresh clone has somewhere to put a
download. `manifest.json` *is* tracked — see [What is tracked](#what-is-tracked).

```
data/
├── raw/                    what was downloaded, untouched
│   ├── <class_name>/*.jpg
│   └── ...
├── processed/              what the model actually reads
│   ├── train/<class_name>/*.jpg
│   ├── val/<class_name>/*.jpg
│   └── test/<class_name>/*.jpg
└── manifest.json           what the split was, and how it was made
```

## raw/

One directory per class; the directory name *is* the label. Nothing writes
here — it is the input, and `prepare_dataset.py` only ever reads it.

```
raw/
├── paddy_bacterial_leaf_blight/
├── paddy_brown_spot/
├── paddy_healthy/
└── ...
```

Class names become directory names on three filesystems and a label in three
languages, so keep them `lower_snake_case`, ASCII, and prefixed by crop. The
label a farmer reads is looked up from this key at serving time — it is never
the string itself, which is why it may stay English here.

## processed/

Written by `scripts/prepare_dataset.py`. Every image is 224×224 RGB JPEG, which
is what the classifier's input layer expects.

**This directory is derived and disposable.** It is rebuilt from `raw/` by
re-running the script with the same seed, which is the whole reason the seed is
recorded. Never edit an image in here, and never add one by hand: the next run
overwrites it and the manifest will describe a corpus that no longer exists.

## manifest.json

Written on every successful run. It is the answer to "which data produced this
model", which is a question a thesis has to answer two years later:

```json
{
  "created_at": "2026-09-20T09:14:22Z",
  "seed": 42,
  "ratios": { "train": 0.7, "val": 0.15, "test": 0.15 },
  "image_size": [224, 224],
  "resize_mode": "cover",
  "classes": ["paddy_brown_spot", "paddy_healthy"],
  "totals": { "raw": 2410, "train": 1687, "val": 361, "test": 362 },
  "per_class": {
    "paddy_brown_spot": { "raw": 1204, "train": 843, "val": 180, "test": 181 }
  },
  "low_count_classes": ["paddy_tungro"],
  "skipped": { "unreadable": 3, "files": ["raw/paddy_healthy/IMG_0912.jpg"] }
}
```

## What is tracked

| Path                    | In git | Why                                              |
| ----------------------- | ------ | ------------------------------------------------ |
| `raw/**`                | no     | large, and licensed by whoever published it       |
| `processed/**`          | no     | derived; `prepare_dataset.py` rebuilds it         |
| `manifest.json`         | **yes**| the record a result is cited against              |
| `../reports/**`         | no     | regenerated by `inspect_dataset.py`               |

`manifest.json` is tracked on purpose and is the one file here worth reviewing
in a diff. A change to it means the corpus moved under a model that was trained
before it — which is exactly the thing that is invisible otherwise.

## Getting a corpus in

1. Download into `raw/`, one directory per class. Nothing in this repo
   downloads anything; the source and its licence are the operator's decision.
2. Look before you split:

   ```bash
   npm run data:inspect      # from the repo root
   ```

   Corrupt files, exact duplicates and the class balance, plus
   `reports/class_distribution.png`.

3. Split and resize:

   ```bash
   npm run data:prepare -- --dry-run   # counts and warnings, writes nothing
   npm run data:prepare
   ```

## Why the split is reproducible, and where that stops

The split is a seeded shuffle of a **sorted** file list, per class. Same files
plus same seed gives the same split on any machine, which is what makes a
reported accuracy checkable.

It is reproducible for a *fixed set of files*. Adding one image to a class
reshuffles that class, so an image that was in `train` can land in `test` — and
a model evaluated after that has been tested on data it was trained on. If the
corpus grows, either re-run everything from scratch and retrain, or move to
assigning each image by a hash of its content, which is stable under additions.
Do not split twice against the same trained model.

## Class balance

`prepare_dataset.py` flags any class with fewer than 100 raw images. The number
is a floor, not a target: below it, a 15% test split is fewer than 15 images, so
test accuracy for that class moves in steps of seven percentage points and
means very little. Treat a flagged class as "collect more or merge it", not as
"the run failed".
